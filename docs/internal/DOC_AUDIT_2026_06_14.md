# Documentation Accuracy Audit

**Date**: 2026-06-14
**Scope**: All 33 published docs.
**Method**: Cross-referenced doc claims against server code (`nina-scheduler-server/packages/server/src/`), web GUI (`packages/user-gui/src/`), Python scheduler (`packages/python-scheduler/`), and the NINA plugin (`packages/plugin/`). Findings carry file:line evidence.
**Prior audit**: `DOC_AUDIT_2026_03_12.md` (most items there resolved; this is a fresh pass covering features added since: subscriptions, announcements/MOTD, reservations, sky flats, demand-driven calibration).

Severity: **HIGH** = feature/page/value described that doesn't exist or contradicts code · **MEDIUM** = partially wrong (label/path/default/missing-in-GUI) · **LOW** = minor/stale wording.

---

## Cross-cutting issues (appear in multiple docs)

### A. NINA minimum version is wrong everywhere — **HIGH**
Docs say **NINA 3.0.0.2001 or later**; the plugin manifest/assembly require **3.2.0.9001**.
Affected: OVERVIEW.md, PLUGIN_SETUP.md, TROUBLESHOOTING.md.
Evidence: `packages/plugin/manifest.json:6`; `NINA.Plugin.ScienceScheduler.csproj:20`; `Properties/AssemblyInfo.cs:45`.

### B. .NET runtime version stated three different ways — **HIGH/MEDIUM**
The plugin targets **only `net8.0-windows7.0`** (single target framework).
- TROUBLESHOOTING.md & GETTING_STARTED.md: ".NET 8.0" (correct, but TROUBLESHOOTING tells users to manually download it)
- OVERVIEW.md: ".NET 10.0 Runtime"
- PLUGIN_SETUP.md / CHANGELOG v2.19 / index.md: "8.0, 9.0, or 10.0 all supported"
- CHANGELOG v2.14: "updated from 8.0 to 10.0 (NINA now targets net10.0)"
Reconcile all to the real single target (.NET 8.0).
Evidence: `packages/plugin/NINA.Plugin.ScienceScheduler.csproj:4`; `global.json:2`.

### C. Observation status count contradicts itself across docs — **HIGH**
Canonical `ObservationStatus` enum has **11** values (`types/observationStatus.ts:15-36`); the Mongoose schema permits 13 strings (`Observation.ts:756-758`).
- SCHEDULER_FEATURES.md says "11 statuses" (correct)
- OBSERVATION_LIFECYCLE.md says "8 statuses" and omits `paused`, `cancelled`, `partially_completed` from prose and state diagram
- CREATING_OBSERVATIONS.md says "8"
- PRACTICAL_GUIDE.md lists 9, omitting `completed_series`/`waiting_next`/`paused`/`expired`

## HIGH severity (per doc)

### CREATING_OBSERVATIONS.md
- **Creation wizard steps wrong**: doc lists Autofocus → Notifications → Review & Submit; actual stepper is `['Project','Target & Exposure','Constraints','Repetition','Autofocus','Guiding','Review & Submit']` — there is a **Guiding** step and **no Notifications step**. Doc also self-contradicts ("6 steps" vs Steps 1–7 in body). Evidence: `pages/user/ObservationSubmit.js:28`.
- **Priority misrepresented as HIGH/MEDIUM/LOW with 30/20/10-min buffer times**: priority is **numeric 1–10** (default 5); no enum, no per-priority buffer mapping. Evidence: `models/Observation.ts:685-691,765-771`; `ObservationSubmit.js:65`.

### OBSERVATION_LIFECYCLE.md
- **Undercounts statuses (8 vs 11)** and omits `paused`/`cancelled`/`partially_completed` from the explanations and the state diagram. Evidence: `types/observationStatus.ts:15-36`; transitions `services/EnhancedObservationStateMachine.ts:393-415`.

### REPETITIVE_OBSERVATIONS.md
- **"Background service runs every 60 seconds" is fabricated** — `RepetitiveScheduler` has no timer/`setInterval`; its methods run on-demand during dispatch. Evidence: `services/RepetitiveScheduler.ts` (no scheduler timer); `server.ts:967-972` (routes only).

### PRACTICAL_GUIDE.md
- **Overhead buffer tiers fabricated** (doc: 20/25/30 min by short/medium/long). Source uses a **flat `OBSERVATION_BUFFER_MINUTES = 10`**, capped at half the exposure duration. Evidence: `python-scheduler/scheduler_core.py:29-31`; `constraint_solver.py:695-708`.
- **Fixed-time buffer claim wrong**: source explicitly **skips the setup buffer for fixed-time observations**. Evidence: `constraint_solver.py:700-710`.

### PROJECTS_GUIDE.md
- **Missing the `can_use` permission** — doc lists 5 member permissions; model + GUI have **6** (omits "Use — submit observations"). Evidence: `models/ProjectMembership.ts:14-21`; `pages/projects/ProjectMemberManagement.js:599-607,678-683`.

### GUIDING_GUIDE.md
- **Dithering default is ON, not Off** — observation form defaults `ditherEnabled: true` ("default true: NINA convention"). Evidence: `pages/user/ObservationSubmit.js:98`; plugin `ServerTarget.cs:256`. (Templates default it false — an internal source inconsistency.)
- **Three guiding toggles, not two** — undocumented third is `requireGuiding` / "Require guiding" (`force_guiding`). Evidence: `pages/user/ObservationSubmit.js:97`; `GuidingStep.js:128-143`.

### CALIBRATION_GUIDE.md
- **All three file-browser calibration chip labels are wrong**: doc says "Calibrated/Cal Failed/No Masters"; actual chips are **"Cal Ready"** (green), **"No Cal"** (orange), **"File Missing"** (red). There is **no "Cal Failed" state**. Evidence: `components/files/FileGrid.js:91-104,199`; `utils/missingCalibrationReason.js:71-73`.
- (Sky/twilight flats, shutterless dark filter, demand-driven calibration all exist and are documented **accurately**.)

### OBSERVATION_FILES.md
- **"Search field to filter files" does not exist** on the Observation Files page — no search/filter input in `pages/observations/ObservationFiles.js`.

### IMAGE_PROCESSING.md
- **"Measures eccentricity" — not measured/reported**. Star analysis computes an elongation ratio only to reject stars (>3.0); never output as a metric. Evidence: `packages/fits-processor/analyze_stars.py`; `services/pipeline/modules/QualityAnalysisModule.ts:61-75`.
- **"Quality metrics shown in the file browser" — grid cards show none** (only filter/exposure/size/solve chips). Metrics appear only in the per-file dialog / detail page. Evidence: `components/files/FileGrid.js:190-205`.

### EXTERNAL_STORAGE.md
- **"File Organization" field documented as a current dialog control — it was removed**. It's a legacy schema field (flat/by_target/by_project_target), converted to a template string and cleared on save; the dialog only has the freeform Storage Path Template. Affects the "Examples" sections too. Evidence: `models/ExternalStorageConfig.ts:93-96`; `externalStorageRoutes.ts:913`; `ExternalStorageDialog.js`.

### ORGANIZATIONS.md
- **Org-as-observatory-member permission inheritance described as fixed grants** (Owner/Admin → can_admin+can_operate; Regular → can_view+can_observe). Actually **edge-capped** by the org's own observatory membership grant — members never get more than the org edge holds. Evidence: `models/Observatory.ts:2663-2675`; `userRoutes.js:901-919`.

### CALIBRATION_ADMINISTRATION.md
- **Read endpoints enforce no observatory scoping** — `library`/`summary`/`needs`/`frames`/`build-attempts`/`readiness`/`cameras` use `requireAuth` only; any logged-in user can read any observatory's calibration data by ID. Doc implies "own observatories" scoping. Also ~14 server-admin maintenance routes are undocumented. Evidence: `routes/calibrationRoutes.ts:278,317,516,549,897`. *(Possible CODE concern, not just doc.)*

### REPORTING_GUIDE.md
- **Admin report URLs are wrong** — doc uses `/reports/{usage,explorer,users,projects,observatories}`; actual routes are `/admin/billing/{dashboard,explorer,users,projects,observatories}`. Following the doc URLs hits the catch-all redirect. Evidence: `App.js:385-389`.
- **"Target Observation Report supports server-side PDF export" — false**. Endpoint returns browser-printable **HTML** (`Content-Type: text/html`, embedded `window.print()`, `.html` filename). Evidence: `routes/reportingRoutes.ts:2540,2767-2771`; `TargetObservationReport.js:206-227`.

### TROUBLESHOOTING.md
- NINA version (issue A) and .NET download instruction (issue B) above.
